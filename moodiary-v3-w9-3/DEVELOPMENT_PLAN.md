# Moodiary 3.0：开发计划与未完成清单

更新时间：2026-11-07。当前接续 W1–W9.2，W9.3 为本轮开发。
基线：`0e64fd9dfe2598bf31209ebafce5dfd282495e32`。
开发分支：`moodiary-v3-w9-3-month-workspace-20261107`。

## 已确认的下一步方案

保留现有普通日记、W1–W8.5 和 W9 的数据库/接口增量。
继续“每个长期主题、每个自然月一个逻辑月度记录，内部含独立记录块及可选总结”的方案。
不自动迁移任何旧用户数据，不开启尚未完成的块级云同步。

本轮 W9.3 完成 PC 月度记录的可操作闭环：

1. 从手机读取可见长期主题，发现 W9 新数据中的月份。
2. 主题/月份切换、按日期分组的时间线、本月搜索及每次 50 条的渐进展示。
3. 使用原有 Tiptap 格式子集追加/编辑；正文修改保留精确事件时间。
4. 单月唯一总结，默认折叠；删除和恢复沿用同一总结身份。
5. 删除转为墓碑，回收站恢复；跨月编辑保留 Block ID 和历史。
6. 保存确认后关闭弹窗、留在原主题/原月份。
7. 丢失回执后锁定不可确认的请求，使用相同操作/版本/正文重试。
8. 409 冲突保留草稿，不自动换父版本覆盖；可主动导出草稿。
9. 事件通知不覆盖正在输入的内容；过期月份读取不能替换当前月份。
10. 读取失败或不兼容格式使缓存转为只读，主题索引和月份内容均校验成功后才恢复写入。
11. 沿用同源、手机配对、CSRF、数据库 CAS 和原有普通日记接口。

PC 不自动把日记正文写入 localStorage/IndexedDB。当前草稿保护覆盖窗口内编辑、
保存失败、冲突和离开提示，并支持用户主动导出 JSON。浏览器刷新/崩溃后的自动
草稿恢复仍需手机侧持久化草稿协议，不能宣称本轮已完成。

## 验收门槛

- 前端类型检查、原有 W7 测试及新增状态/组件测试。
- 生产打包后的真实 Chromium：普通日记回归、主题/月度发现、实际 Tiptap 格式、
  丢失回执、重复提交、远端通知、跨月移动、删除恢复、总结、冲突导出、窄屏布局。
- 原有 v2/v3→v4 迁移、真实 SQLite 文件重开、HTTP 授权/撤销和 WebDAV 回归。
- 全部通过后构建 ARM64 APK，核对包名、ABI、资源和 SHA-256。
- 自动化通过只放行开发验证包，不替代真机与正式数据恢复验收。

本地已通过前端 30 项测试和 TypeScript 检查。CI 及浏览器验收结果待补充。
本地 Chromium 被执行环境拒绝本机 socket；浏览器验收在 CI 执行。
